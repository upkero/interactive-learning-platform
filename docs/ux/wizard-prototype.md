# Прототип мастера генерации (Э2 → Э3 → Э4 → Э5 → Э6)

## 1. Кликабельный прототип

**Ссылка:** [docs/ux/prototype/index.html](./prototype/index.html)

Откройте файл напрямую в браузере (двойной клик или `open docs/ux/prototype/index.html`) — это самодостаточный HTML+CSS+JS без сборки.

### Панель симуляции (сверху)
Переключатели сценариев позволяют в 1 клик проверять нештатные ветки:
- **Квота: хватает / не хватает на Э3** — блокирует переход Э3→Э4, показывает предупреждение с нехваткой генераций
- **Гонка вкладок: не хватает квоты при отправке Э4** — на Э4 появляется баннер «Квота исчерпана (гонка вкладок)», кнопка «Запустить генерацию» отключена
- **Google Docs: ошибка gdocs_not_public** — на Э2 после имитации загрузки показывается ошибка с кодом `gdocs_not_public`
- **Э5: одна часть упала (failed)** — вторая часть получает статус `failed`, кнопки «Повторить» нет, есть текст «Генерация возвращена» и кнопка возврата на Э3

### Строка URL-маршрута
Под панелью симуляции всегда виден текущий маршрут:
- **Э2:** `/upload?document={id}`
- **Э3:** `/documents/{id}/topics` (БЕЗ `?topics=` в URL)
- **Э4:** `/documents/{id}/questions?topics=id1,id2` (только `topics` в query, БЕЗ `level/depth/goal`)
- **Э5:** `/documents/{id}/progress`
- **Э6 (переход по кнопке «Открыть»):** `/parts/{id}`

### Основной сценарий (прокликайте по порядку)
1. **Э2** — кликните на зону загрузки или вставьте ссылку → «Импортировать» → увидите карточку разбора `uploaded → parsing → parsed` → автопереход на Э3
2. **Э3** — отметьте 1–2 темы → счётчик «Будет использовано N из M» + пояснение «Генерация вернётся, если обработка сорвётся по вине системы» → превью частей → «Далее»
3. **Э4** — вопросы предзаполнены из `GET /api/v1/me → last_answers` (указан источник под каждым) → вопрос 1 (уровень) обязателен → блок подтверждения списания → «Запустить генерацию»
4. **Э5** — список частей с прогресс-барами, ETA, журнал этапов → у `published` частей активна кнопка «Открыть» → клик → **Э6** (`/parts/{id}`)
5. **Э6** — превью перехода: показан URL `/parts/{id}`, кнопки возврата на Э5 и Э1

### Нештатные ветки (включите чекбоксы в панели симуляции)
- **Квота не хватает** → на Э3 кнопка «Далее» заблокирована, красное предупреждение с цифрой нехватки
- **Гонка вкладок** → на Э4 баннер «Квота исчерпана», кнопка запуска отключена, возврат на Э3
- **Google Docs ошибка** → на Э2 после разбора — модалка с кодом `gdocs_not_public`, кнопки «Попробовать другую ссылку» / «Выбрать файл»
- **Часть упала** → на Э5 вторая часть `failed`, серый индикатор, текст «Генерация возвращена», остальные продолжаются, кнопка «← Вернуться к выбору тем» (НЕТ кнопки «Повторить часть»)

## 2. Соответствие документам

- **Правила переходов** — см. [docs/ux/screens.md](../screens.md) (разделы 1–3). Дублирование убрано.
- **Статусы бэкенда** — ровно 6: `uploaded`, `parsing`, `parsed`, `generating`, `done`, `failed` (нет `topics_required`, `questions_required`, `ready`, `error`, `parsing_failed`).
- **Маршруты** — согласованы: Э2 `/upload?document={id}`, Э3 `/documents/{id}/topics` (без `?topics=`), Э4 `/documents/{id}/questions?topics=id1,id2` (только topics), Э5 `/documents/{id}/progress`, Э6 `/parts/{id}`.
- **Поведение упавшей части** — нет кнопки Retry, есть возврат на Э3 для повторного запуска.
- **Чекбокс почтовых уведомлений (PATCH /me)** — убран (нет в методичке).
- **NEXT_PUBLIC_API_URL / api.<домен>** — не упоминаются.

## 3. Ключевые детали экранов (для реализации)

### Э2 — Загрузка / Разбор
- Dropzone: файл (PDF/DOCX/MD ≤ 50 МБ) или ссылка Google Docs
- После импорта — `ParsingCard` с шагами: `uploaded` → `parsing` → `parsed`
- Ошибка Google Docs: `gdocs_not_public` (баннер с действиями)
- Автопереход на Э3 при `parsed`

### Э3 — Выбор тем
- Дерево тем с чекбоксами, стоимость каждой темы в генерациях
- Счётчик: «Будет использовано N из M» + пояснение про возврат генераций при системном сбое
- Превью структуры частей (PlanPreview)
- Валидация квоты: `cost <= quota.remaining`, иначе блокировка + предупреждение
- Навигация: «Назад» → Э2, «Далее» → Э4 (сохраняет `topics` в URL query)

### Э4 — Параметры генерации
- 3 вопроса: уровень (обязательный), глубина, цель — radio-группы
- Предзаполнение из `GET /api/v1/me → last_answers` (источник указан в UI)
- Блок подтверждения: `confirmSpend` (cost, remaining, total)
- Кнопка «Запустить генерацию» → `POST /documents/{id}/generate` → 202 → Э5
- Гонка вкладок: если квота изменилась — 402, баннер, возврат на Э3
- Навигация: «Назад» → Э3 (всегда разрешено), Э5→Э4 **запрещено** после 202

### Э5 — Прогресс
- ETA таймер, живой журнал этапов (StageLog)
- Карточки частей (`PartCards`) с прогресс-барами и статусами: `queued` → `generating` → `published` / `failed`
- У `published`: кнопка «Открыть» → `/parts/{id}` (не ждём `document_done`, не `/documents/[id]`)
- У `failed`: серый индикатор, текст «Генерация возвращена», остальные части продолжаются
- Кнопка «← Вернуться к выбору тем» (Э3) для повторного запуска
- Кнопка «← Вернуться к материалам» (Э1) в любой момент
- KeyTerms появляются по мере генерации

### Э6 — Материал (превью в прототипе)
- Маршрут `/parts/{id}` (конкретная часть, не весь документ)
- Кнопки: «← Вернуться к прогрессу», «← Вернуться к материалам», «Пройти тест по части →»

### Э8 — Поделиться
- Модальный диалог поверх Э6 или Э1
- Доступно только `role = owner`
