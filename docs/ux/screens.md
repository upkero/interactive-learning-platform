## 3. Редиректы при прямом заходе по ссылке на «чужой» шаг мастера

Если пользователь открывает URL шага мастера, который не соответствует актуальному `document_status` документа на сервере, выполняется принудительный `router.replace`:

* Документ в `uploaded` / `parsing` → любой заход на `/topics`, `/questions`, `/progress`, `/parts/{id}` редиректит на `/upload?document={id}`.
* Документ в `parsed` → заход на `/questions`, `/progress`, `/parts/{id}` редиректит на `/documents/{id}/topics`.
* Документ в `generating` → заход на `/topics`, `/questions`, `/parts/{id}` редиректит на `/documents/{id}/progress`.
* Документ в `done` → заход на `/topics`, `/questions`, `/progress` редиректит на `/parts/{part_id}` (первая опубликованная часть).
* Документ в `failed` → заход на `/questions`, `/progress`, `/parts/{id}` редиректит на `/documents/{id}/topics` (переход назад на `/upload?document={id}` разрешён).

## 6. Нештатные ситуации, ETA и таблица проверки

### 6.1. Сбой части (Б-12.2)

На экране **Э5 (Прогресс)** при получении события `part_status = failed` для какой-либо части:

* **Никакой кнопки «Повторить часть»** — в MVP эндпоинта повторной генерации отдельной части нет. Повтор возможен только через возврат на **Э3 (Выбор тем)** и повторный запуск генерации.
* **Отображение упавшей части:**
  - Текст: **«Не получилось обработать часть. Генерация возвращена»**
  - Серый индикатор статуса (бейдж `failed` в нейтральном сером цвете)
  - Прогресс-бар части заполнен полностью, но окрашен в серый
* **Остальные части** продолжают генерироваться в штатном режиме.
* **Квота:** генерации за упавшие части **уже возвращены в квоту** (на бэкенде списание происходит только за `published` части).
* **Действие пользователя:** кнопка **«← Вернуться к выбору тем» (Э3)** для повторного запуска генерации.

**Если упали все части документа** (документ переходит в статус `failed`):
* На **Э1 (Мои материалы)** в строке документа показывается: **«Сбой, генерации возвращены»**
* Клик по строке → **Э3 (Выбор тем)** для повторного запуска.

### 6.3. Формула ETA (Б-12.4, М-12.1)

**Формула (inline code):** `ETA = round(mean(duration готовых частей) × (N_total − N_done))`

* **Источник длительностей:** timestamps событий `part_ready` (получаются через SSE: `event: part_ready`, поле `duration_ms` или разница между `started_at` и `completed_at`).
* **Показывать ETA ТОЛЬКО при `N_done >= 1`** — то есть после первой готовой части со статусом `published`.
* До первой готовой части **ничего не показывать** (ни «0 мин», ни выдуманные константы вроде 25 с / 5 с / 0.8·T_avg).
* Формат вывода: `≈ {N} мин` (округление до целых минут).
* Пример: готово 2 части из 5, средняя длительность 3 мин → `ETA = round(3 × (5−2)) = 9` → показываем `≈ 9 мин`.

### 6.4. Коды ошибок, лимиты и квота (В-12.1, В-12.2, В-12.4)

#### Замена несуществующих кодов на реальные `DocumentErrorCode`

| Было (неверно) | Стало (правильно) |
|---|---|
| `parsing_failed` / `errors.parsing_failed` | Конкретные коды: `parse_failed`, `gdocs_not_public`, `gdocs_import_failed`, `too_many_pages`, `empty_document`, `enqueue_failed` |
| Статус `ready` (для части) | `published` |
| Статус `ready` (для документа) | `done` |
| Статус `error` | `failed` |

#### Сбой разбора на Э2 (документ в `failed`, `error_code` из `DocumentErrorCode`)

* **Квота не списывается** при любых ошибках разбора.
* Кнопка: **«Загрузить другой файл»** (возврат к загрузке).
* Таблица маппинга `error_code` → пользовательский текст:

| `error_code` | Текст для пользователя |
|---|---|
| `parse_failed` | `Не удалось разобрать структуру документа. Попробуйте другой файл.` |
| `gdocs_not_public` | `Не удалось получить доступ к Google Docs. Проверьте, открыт ли доступ по ссылке для просмотра.` |
| `gdocs_import_failed` | `Не удалось импортировать Google Docs. Попробуйте скачать файл и загрузить его напрямую.` |
| `too_many_pages` | `В документе слишком много страниц. Максимум — 500 стр.` |
| `empty_document` | `Документ пуст или не содержит распознаваемого текста.` |
| `enqueue_failed` | `Не удалось поставить задачу в очередь. Попробуйте загрузить файл позже.` |

#### `quota_exceeded` (нехватка генераций при запуске)

* HTTP код: **`402 Payment Required`** (убрать `409 Conflict`).
* На Э3/Э4: блокировка перехода/запуска + текст из раздела 6.2.

#### `processing_limit_reached` (лимит активных документов)

* Константа: `PROCESSING_MAX_ACTIVE_DOCUMENTS = 2`.
* HTTP код: **`429 Too Many Requests`**.
* Поля ответа: `limit` (текущий лимит, 2).
* Текст: `У вас уже обрабатывается 2 документа. Дождитесь завершения или удалите лишний.`
* На Э2 (после загрузки): баннер с текстом, кнопка «Ок» — остаться на Э2.

#### `queue_unavailable` (очередь недоступна)

* HTTP код: **`503 Service Unavailable`**.
* Документ сразу переводится в статус `failed` (`error_code = enqueue_failed`).
* Лимит активных документов **не занят** (слот освобождается).
* На Э2: текст `Сервис временно недоступен. Попробуйте загрузить файл позже.` + кнопка «Повторить загрузку».

#### Квота: дефолт и граница периода

* `QUOTA_DEFAULT_MONTHLY_LIMIT = 20` генераций в месяц.
* Период: `period_start` (включительно) — `period_end` (исключительно).
* В тексте «Счётчик обновится {date}» дата = **`period_end − 1 день`** (последний день текущего периода).

### 6.5. Потеря связи / SSE (В-12.5)

* **Подключение:** `EventSource` по относительному пути `/api/v1/documents/{id}/events` **без `withCredentials`** (единый домен `/api`, куки идут автоматически).
* **Переподключение:** стандартное поведение `EventSource` (браузер сам переподключается с `Last-Event-ID` заголовком). Максимум **5 попыток** с экспоненциальным бэкоффом (1 с, 2 с, 4 с, 8 с, 16 с). После 5-й неудачи — показ «Связь потеряна» + кнопка «Обновить».
* **Сверка с контрактом SSE 1.7:** события `stage_start`, `stage_complete`, `part_ready`, `document_done` содержат `event_id` для идемпотентности. Клиент должен сохранять последний полученный `event_id` и при ручном переподключении (кнопка «Обновить») передавать его через заголовок `Last-Event-ID` (стандартный механизм `EventSource`).

> В прототипе (PR #11) используется упрощённая симуляция без реального SSE.
