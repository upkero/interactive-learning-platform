# ADR-0010. Контракт примитивов

- Статус: Предложено
- Дата: 2026-11-09
- Автор: Фронтенд/Визуализация
- Затрагивает: SCRUM-123, 3.4, резолвер и приложение

## Контекст

Резолвер, сервер и приложение должны одинаково интерпретировать параметры и
режим виджета. Контракт нужен до реализации учебных примитивов, чтобы их схемы,
примеры и отображение не расходились.

## Варианты

1. Отдельные схемы для каждого потребителя: гибко, но легко получить расхождения.
2. Единое определение на Zod с экспортом JSON Schema: одна точка описания,
   но разрешены только конструкции, представимые в JSON Schema.

## Решение

Выбран второй вариант. `PrimitiveDefinition` задаёт id, semver, описание,
схему, поддерживаемые режимы, компонент, подписи и 2–4 примера. На каждый
MVP-режим нужен пример. `PrimitiveProps` содержит разобранные параметры,
режим, словарь и обработчик событий. `SceneProps` передаёт сцене кадр, индекс,
параметры и подписи. Режим выбирает конфигурация виджета, ученик его не меняет.

Чистая `buildFrames` создаёт не более 200 кадров; вопрос о переходе хранится в
кадре. События: `step`, `predict`, `complete`. Watch запускается при видимости,
кроме reduced motion; пользователь может поставить воспроизведение на паузу.

Схема имеет английское `.meta({ description })` на каждом поле, включая
дискриминаторы, и границы значений. `refine`, `superRefine`, `transform`,
`pipe`, `custom` и `overwrite` запрещены. Экспорт `io: "input"` сохраняет
необязательность полей с default: примеры соответствуют входному типу, а
компонент получает выход `safeParse` с применёнными значениями по умолчанию.
Подписи — плоские ключи `common.*` и `<id>.*` в ru/en; переменные передаются
через `{name}`. Правила множественного числа согласовываются при появлении
первого примитива, которому они нужны.

Каталог — объект `{ catalogVersion, design: { checklist, tokens, uiExports },
primitives }`. Каждая запись содержит `id`, `version`, `title`, `description`,
`modes`, `paramsSchema`, `labelKeys`, `examples`. Ключи JSON — camelCase;
Python-потребитель отображает их на свои snake_case-поля. Каталог
детерминированно генерируется и версионируется через `catalogVersion`.
Несовместимое изменение схемы примитива повышает его major-версию; при ошибке
`safeParse` приложение показывает fallback и регистрирует клиентское событие.

Новый примитив: определить схему и описания, чистый построитель кадров и сцену,
примеры для всех режимов, словари и истории; зарегистрировать определение,
обновить каталог и проверить схемы, клавиатуру, темы и мобильную ширину.

## Последствия

Контракт требует согласования лида до 3.4. Backend владеет интеграцией сидера и
Python-проверкой JSON Schema; приложение — fallback и логированием. Отдельно
нужно решить хранение примеров и версии примитива, а также нормализацию default
перед дедупликацией резолвера. Пересмотреть ADR при изменении этих интеграций.
