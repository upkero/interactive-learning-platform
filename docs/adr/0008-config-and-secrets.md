# ADR-0008. Конфигурация через переменные окружения и секреты

- Статус: Принято
- Дата: 2026-10-19
- Автор: Илья, Бэкенд/DevOps
- Затрагивает: истории 1.1, 1.2, 1.3, 1.4, 2.1

## Контекст

Приложению требуются десятки параметров (подключение к БД, S3, Redis, секреты JWT, лимиты загрузок). Хранить их в коде небезопасно, а использование сырого `os.getenv` приводит к отсутствию валидации типов при старте приложения.

## Варианты

1. Чтение через `os.getenv` напрямую в сервисах — минус: отсутствие валидации типов, риск запуска приложения с неполной конфигурацией.
2. Единые классы настроек Pydantic `BaseSettings` по доменным областям — строгая валидация типов, защита от запуска без обязательных секретов.

## Решение

Все параметры разделены по доменным классам `BaseSettings` в `core/settings/` с фиксированными префиксами (`AUTH_`, `S3_`, `UPLOAD_` и т.д.). Ключ `AUTH_JWT_SECRET` объявлен обязательным без дефолтного значения. Все параметры задокументированы в `backend/.env.example`. В production секреты передаются через GitHub Secrets и `.env` на сервере с правами 600.

## Последствия

Приложение валидирует все параметры до старта. Запуск без обязательных секретов завершается явной ошибкой `ValidationError`.
